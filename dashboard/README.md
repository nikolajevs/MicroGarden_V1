# Панель телеметрии MicroGarden (dash.dvinsk.lat)

Замена Ubidots: плата раз в минуту присылает показания и новые строки своего журнала
(то, что она печатает в Serial) на собственный сервер, а страница показывает графики и
сообщения об ошибках. Люди регистрируются на сайте сами, добавляют свои платы и получают токены;
каждый видит только свои платы. Сервер — один файл на стандартной библиотеке Python 3.9+ и SQLite,
страница — обычный HTML, CSS и JavaScript без внешних библиотек и CDN.

```text
плата ESP32 ──HTTPS POST /api/ingest──▶ Traefik (93.127.143.133) ──▶ nginx на VPS :80 ──▶ server.py :8790
                                         HTTPS и сертификат                              (pm2)      │
браузер ◀──── страница, графики, журнал ◀────────────────────────────────────────────────────────── SQLite
```

## Что на странице

- Карточки с текущими показаниями: температура, влажность, свет, вентиляторы, мощность,
  энергия за сутки, помпа, нагреватель. Версия прошивки, уровень Wi-Fi и время работы платы
  стоят в строке под названием. Отдельных значков состояния нет: неисправности датчиков, часов,
  SD-карты и измерителя питания показывает колокольчик.
- Графики за 6 часов, сутки, 7 или 30 дней: температура и влажность; свет и вентиляторы с
  полосами работы помпы и нагревателя; мощность и напряжение шины с порогом 21,6 В.
  Простой связи рисуется разрывом линии, а не ровной чертой.
- Список сообщений платы из Serial: по умолчанию только ошибки, можно добавить
  предупреждения или показать всё. Ошибка — например «Датчик перестал отвечать»,
  «Аварийная остановка», «Не отвечает» (правила в `classify()` в `server.py`).
- Выгрузка CSV за выбранный период (колонки как в файлах на SD-карте платы плюс питание).
- Кнопка **«Настройки платы»** над графиками открывает страницу `/settings`: настройки, которые плата сама
  сообщила, и их правка из браузера (раздел «Настройки платы из панели» ниже).
- Кнопки в шапке: «Платы» (значок микросхемы, страница `/boards`: платы и их токены), «Аккаунт» (значок
  человека: смена пароля и выход) и у администратора «Люди» (страница `/admin`). Подробнее в разделах
  «Люди и регистрация» и «Платы и токены». В списке плат над графиками стоят названия, которые вы им дали.
  Пока у человека нет данных, под шапкой стоит подсказка, как подключить плату.
- **Колокольчик** в шапке с числом оповещений и списком по нажатию (закрывается кликом вне списка
  или Esc; число дублируется в заголовке вкладки). Оповещения — то, что требует внимания
  **сейчас**, они пропадают, когда причина устранена; цвет колокольчика и счётчика — по самому
  тяжёлому: серый (нет), жёлтый (предупреждения), красный (что-то не работает). При росте числа
  оповещений колокольчик качается. Что в списке:

  | Оповещение | Уровень |
  |---|---|
  | Нет связи с платой (данные не приходят дольше 3 минут; дольше часа — красное) | жёлтый / красный |
  | Датчик SHT4x не отвечает | красный |
  | Часы RTC: нет времени / идут по программному таймеру | красный / жёлтый |
  | Свет выключен: питание ниже 21,6 В, или нет данных питания и времени | красный |
  | Измеритель питания не отвечает, свет работает без защиты | жёлтый |
  | В баке нет воды; последний полив пропущен | жёлтый |
  | SD-карта не обнаружена | жёлтый |
  | Ошибки в журнале платы за последний час (пункт «Показать» открывает журнал) | жёлтый |
  | Нет связи с сервером панели (страница не получила ответ) | красный |

  Пока плата молчит, её последние показания могли устареть, поэтому неисправности из них
  помечаются «(по последним данным)». В режиме сушки оповещения про свет и полив не показываются.
  Правила лежат в `dashboard/static/alerts.js` и **совпадают с главной страницей платы**
  (`firmware/data/alerts.js`): тест `tests/dashboard-alerts-parity.test.cjs` проверяет, что для
  всех 1024 сочетаний состояний оба файла дают одни и те же оповещения.

## Что присылает плата

`POST /api/ingest` с заголовком `Authorization: Bearer <токен приёма>` и телом JSON до 64 КБ:

```json
{
  "device": "microgarden-v1",
  "sample": {
    "temp": 24.5, "hum": 55.2, "led": 120, "fan1": 80, "fan2": 80,
    "power_w": 45.1, "bus_v": 24.1, "current_a": 1.87, "energy_kwh": 0.123,
    "pump": false, "heater": false, "led_blocked": false, "sht_ok": true, "rtc_ok": true,
    "clock_trusted": true, "clock_usable": true, "sd_ok": true, "power_ok": true, "water_sensor": true,
    "water_present": true, "water_skipped": false, "op_mode": 0,
    "rssi": -61, "heap_free": 120000, "uptime_s": 3600, "fw": "lite-1"
  },
  "log": { "boot": "a1b2c3d4", "from": 1500, "text": "[ПОЛИВ] Старт автополива\n" },
  "cfg": { "cloud": true, "id": "1a2b3c4d", "res": "ok", "v": { "temp_target": 25.0, "led_on_hour": 6, "heater_mode": 3 } }
}
```

- `led`, `fan1`, `fan2` — ШИМ 0–255, как в `/api/status` платы; `energy_kwh` — с полуночи платы.
- Поля для оповещений: `clock_usable` — есть время, которому можно верить (RTC или выставленный
  программный таймер), `water_skipped` — последний запланированный полив пропущен, `op_mode` —
  0 выращивание, 1 сушка. Старая прошивка их не присылает: оповещения тогда считаются без них
  (нет `clock_usable` — считаем, что времени нет; нет `op_mode` — считаем, что идёт выращивание).
- Поле, которого нет или значение вне допустимого диапазона, сервер отбрасывает. Если
  `sht_ok` равно `false`, температура и влажность в график не попадают.
- Время записи — время приёма на сервере: часы платы идут по местному времени без пояса и
  могут быть не выставлены.
- `log` — порция журнала. `from` — сколько байт журнала плата отправила с момента запуска, а
  `boot` — случайный номер запуска. Повторная отправка той же порции безопасна (сервер берёт
  только новые байты), пропуск и перезагрузка платы помечаются в списке сообщений строками
  «пропущено N байт» и «плата перезагрузилась». Без `boot` порция отклоняется. Байты, не
  являющиеся UTF-8 (например, строка, обрезанная посреди русской буквы), заменяются знаком
  подстановки, запрос из-за них не отклоняется.
- `cfg` — настройки платы (прошивка, которая умеет менять их из панели; старая раздела не присылает).
  `cloud` — разрешила ли плата менять настройки из панели, `id` и `res` — последний запрос панели, который
  она обработала, и итог (`ok` или причина отказа: `range:<имя>`, `param:<имя>`, `order:<пара>`), `v` —
  текущие значения. Подробнее в разделе «Настройки платы из панели».
- Ответ: `{"ok":true,"log_next":N,...}`; если для платы есть запрос на изменение настроек и она его принимает,
  в ответе ещё `"cfg":{"id":"1a2b3c4d","set":{"temp_target":24.5}}`. `401` — неверный или отозванный токен, `403` — плата не
  зарегистрирована на странице «Платы» или токен выдан другой плате, `400` — неверные данные,
  `413` — слишком большой запрос.

Остальные запросы (`/`, `/boards`, `/account`, `/admin`, `/api/status`, `/api/series`, `/api/logs`,
`/api/export.csv`, `/api/devices`, `/api/boards`, `/api/tokens/…`) требуют входа: страницы без входа
ведут на `/login`, запросы данных получают `401`. Открыты только `/healthz`, страницы входа и регистрации,
их скрипты и стили и состояние регистрации (`/api/registration`).

## Люди и регистрация

Регистрация **открыта для всех**, у кого есть адрес сайта: страница `/register`, имя и пароль, почта
не нужна. После регистрации человек сразу вошёл и попадает на страницу «Платы».

- **Имя**: 3-32 символа, латиница, цифры, `_ . -`; заглавные и строчные не различаются (`Ivan` и `ivan`
  одно имя); `admin`, `root` и похожие зарезервированы. **Пароль**: 10-128 символов, не из одних
  пробелов, не равен имени. Пароли хранятся только как scrypt с отдельной солью (`N=16384`, `r=8`, `p=1`).
- **Вход**: страница `/login`, потом cookie `dash_session` на 30 дней (`HttpOnly`, `SameSite=Lax`, а за
  HTTPS и `Secure`; значение в базе лежит только как SHA-256). Срок продлевается, пока человек пользуется
  панелью. «Выйти» закрывает сессию; смена пароля закрывает остальные входы человека.
- **Кто что видит.** Человек видит и меняет только свои платы, их токены, показания и журнал; чужая плата
  для него выглядит как «нет данных». **Администратор** (имя из `DASH_VIEW_USER`, пароль из
  `DASH_VIEW_PASSWORD` в `.env`, пароль меняется только там) видит все платы с именами владельцев и общий токен
  из `.env`. Платы, которые были до учётных записей, при первом запуске достаются администратору.
- **Пароль забыт.** Почты в системе нет, поэтому пароль сбрасывает администратор на странице `/admin`: он
  получает одноразовый временный пароль и передаёт его человеку, все прежние входы закрываются.
- **Страница `/admin`** (только администратору): кнопка «Закрыть регистрацию» / «Открыть регистрацию»;
  список людей с числом плат, временем последнего входа и адресом регистрации; «Заблокировать» (вход закрыт,
  сессии оборваны, платы перестают присылать данные), «Разблокировать», «Сбросить пароль», «Удалить»
  (вместе с платами, показаниями и журналом).
- **Защита от злоупотреблений**, раз регистрация открыта:

  | Что ограничено | Предел |
  |---|---|
  | Попытки регистрации с одного адреса | 10 в час (`REGISTRATIONS_PER_HOUR`) |
  | Неверные пароли и токены с одного адреса | 10 за 10 минут, потом блокировка адреса на 10 минут |
  | Неверные пароли одному имени | 20 за 10 минут |
  | Человек на сервере | 200 (`DASH_MAX_USERS`) |
  | Плат у одного человека | 3 (`DASH_MAX_BOARDS_PER_USER`), у администратора без предела |
  | Плат на сервере | 100 (`DASH_MAX_BOARDS`) |
  | Приём данных от одной платы | не чаще раза в 5 секунд (`429`), обычная плата шлёт раз в минуту |

  Успешный вход счётчик неудач не сбрасывает: иначе своим входом между чужими подборами лимит не обойти.
  Если появились лишние записи, регистрацию закрывают одной кнопкой, а ненужные записи блокируют или удаляют.
- **Настройки в `.env`** (необязательны): `DASH_REGISTRATION=open|closed` (начальное состояние; потом его
  переключает администратор), `DASH_MAX_USERS`, `DASH_MAX_BOARDS_PER_USER`, `DASH_MAX_BOARDS`,
  `DASH_SESSION_DAYS` (30), `DASH_COOKIE_SECURE=1` (ставить `Secure` всегда, а не по заголовку
  `X-Forwarded-Proto` от Traefik).
- **Скрипты и проверка администратором.** Администратор может прислать HTTP Basic (имя и пароль из
  `.env`), как раньше (`curl -u`); у обычных людей такого входа нет. Неверный Basic считается неудачным входом.

## Платы и токены

Данные принимаются только от **зарегистрированных** плат. Каждый человек добавляет свои платы на странице
`/boards` (кнопка «Платы» в шапке); править `.env` и заходить на сервер по ssh для этого не нужно.

**Добавить плату:**

1. «Добавить плату»: название («Теплица») и имя платы в системе (`microgarden-2`, латиница, цифры,
   `_ . -`, без повторов; страница подсказывает свободное).
2. Страница один раз показывает три значения для настроек платы: адрес приёма (`https://…/api/ingest`),
   имя платы и токен, у каждого своя кнопка «Копировать».
3. В настройках платы (вкладка «WiFi», раздел «Телеметрия») введите адрес, имя платы и токен,
   нажмите «Сохранить телеметрию». Через минуту плата получит статус «Онлайн».

**Карточка платы** (по две в ряд на компьютере, по одной на телефоне): слева цветная полоса по связи, название
и имя платы, значки «Онлайн», «Нет связи · N мин назад» или «Нет данных», версия прошивки (администратору ещё
имя владельца чужой платы), действующие токены строкой «название, начало токена, когда использовался»,
кнопки «Токен» (новый), «Настройки» и «Графики» (ведут на страницы именно этой платы). Переименование и
удаление платы лежат в меню «…» в углу, отозванные токены свёрнуты под строкой «Отозванные». Подтверждение
(отозвать токен, удалить плату) появляется полосой в самой карточке, окон браузера нет.

- **Токен привязан к плате.** Он принимает данные только под её именем: с токеном одной платы
  нельзя писать данные от имени другой. Токен выглядит как `mgd_…` (47 символов, плата принимает от 24 до 128).
- **Замена токена без перерыва:** кнопка «Токен», введите новый в плату, потом отзовите старый (значок
  «⊘» в его строке). Отозванный токен перестаёт действовать сразу; запись о нём можно удалить.
- **Удалить плату** можно, когда у неё нет действующих токенов (в меню «…» пункт неактивен, пока они есть);
  удаляются её показания, журнал и токены. Это нельзя отменить (страница просит подтверждение).
- **Общий токен из `.env`** (`DASH_INGEST_TOKEN`), если он задан, видит и отзывает только администратор;
  он подходит любой зарегистрированной плате. Он нужен, чтобы уже настроенная плата продолжала работать после
  обновления. Заменили токен в `.env` или убрали его — прежний сразу перестаёт действовать; отозванный
  на странице он не возвращается при перезапуске. Надёжнее выдать каждой плате свой токен и убрать общий.
- **Переход со старой версии.** При первом запуске с реестром плат все платы, которые уже присылали
  данные, регистрируются сами (название равно имени платы, его можно изменить), поэтому приём не
  прерывается. Токены в базе хранятся только в виде SHA-256: показать токен повторно невозможно, а при
  утере его заменяют новым.
- **Имя платы одно на весь сервер**: занятое имя занять нельзя, поэтому чужую плату «присвоить» не выйдет.
  Плата заблокированного человека присылать данные перестаёт.
- Пределы: 200 действующих токенов, 500 записей о токенах (с отозванными); плат у человека и на сервере
  см. таблицу выше.

API (для справки, все запросы только после входа): `GET /api/me`, `POST /api/login`, `POST /api/register`,
`POST /api/logout`, `POST /api/account/password`, `GET /api/boards`, `POST /api/boards`,
`POST /api/boards/<имя>/tokens`, `POST /api/boards/<имя>/rename`, `DELETE /api/boards/<имя>`,
`POST /api/tokens/<номер>/revoke`, `DELETE /api/tokens/<номер>`; администратору ещё
`GET /api/admin/users`, `POST /api/admin/users/<номер>/disable|enable|reset-password`,
`DELETE /api/admin/users/<номер>`, `POST /api/admin/registration`. Чужие платы и токены человеку не
показываются и не изменяются (ответ `404`). Всё, что меняет данные (в том числе вход и регистрация), принимается
только с заголовком `X-Dash-Action: 1` и телом `application/json`: чужая страница не может его отправить
(сервер не разрешает CORS), поэтому не может войти, зарегистрировать или удалить плату от имени человека
(защита от CSRF); запросы с `Sec-Fetch-Site`, отличным от `same-origin`, отклоняются.

## Настройки платы из панели

Кнопка «Настройки платы» над графиками открывает страницу `/settings`: на ней видны настройки, которые плата
сама сообщила, и их можно изменить из браузера. Плата забирает изменение с очередной отправкой данных (раз в
минуту) и применяет его так, будто владелец сохранил форму на её собственной странице настроек.

**Как это работает**

1. Плата в каждой отправке добавляет раздел `cfg`: разрешено ли менять настройки из панели, номер последнего
   обработанного запроса с итогом и текущие значения (`v`). Панель всегда показывает то, что стоит на плате
   на самом деле, в том числе после правки на её собственной странице.
2. Вы меняете значения и нажимаете «Применить». Сервер проверяет их по таблице пределов и ставит запрос в
   очередь: на плату один ждущий запрос, новые правки дополняют его, а значения, которые уже так стоят на плате,
   не отправляются. Запрос живёт 10 минут: если плата за это время не вышла на связь, он снимается, чтобы
   устаревшее изменение не сработало потом.
3. В ответе на очередную отправку сервер прикладывает запрос:
   `"cfg":{"id":"1a2b3c4d","set":{"temp_target":24.5,"led_on_hour":7}}`.
4. Плата применяет запрос, только если владелец разрешил это на её странице настроек (вкладка «WiFi», раздел
   «Телеметрия», галочка «Разрешить менять настройки платы из панели»; **по умолчанию выключена**), и только
   целиком: одно неподходящее значение отклоняет весь запрос. Значения она проверяет по своей таблице пределов
   (как при сохранении формы) и сохраняет в NVS так же, как форма. Тот же номер запроса дважды не применяется.
5. В следующей отправке плата возвращает номер запроса и итог; страница показывает «Применено платой» или
   «Плата не применила: …». В журнал платы (и на панель, в «Сообщения платы») попадает строка
   `[Cloud] Настройки из панели применены (…): temp_target=24.5, led_on_hour=7`.

**Что можно менять:** режим (выращивание или сушка), климат (день, ночь, сушка), расписание и мощность света,
пределы вентиляторов, режим обогревателя, расписание полива и его длительность, яркость и ночной режим
индикатора, дату начала цикла. **Нельзя** (меняется только на самой плате): WiFi и точка доступа, адрес и
токен панели, имя платы, поправка тока, датчик уровня воды (его отключение снимает защиту насоса от пустого
бака) и сам выключатель. Длительность полива из панели не больше 300 с (на плате можно до 3600 с). Если минимум
больше максимума (лампа, вентиляторы), страница и сервер отклоняют правку. Список ведут `CFG_SPECS` в `server.py`
и `CLOUD_PARAMS` в `firmware/CloudSettings.h`; тест сверяет оба списка и пределы с таблицей `SETTING_DEFS`.

**Поля по режиму.** Как и на странице самой платы, показываются только настройки, которые в текущем режиме
работают: в **сушке** нет освещения, автополива, климата при выращивании и цикла выращивания (свет и полив
выключены), в **выращивании** нет климата сушки. Набор полей меняется сразу, как только в форме выбран другой
режим; под формой написано, что спрятано и как это увидеть. Правки спрятанных полей не отправляются: что не
видно, то не меняется. Какая группа в каком режиме работает, задаёт поле `modes` у групп в `CFG_GROUPS`
(`server.py`); тест сверяет его со страницей платы.

**Кто может:** человек для своей платы, администратор для любой. Правки пишутся в историю (кто, когда, что,
итог); владелец платы видит и правки администратора. Чужая плата, как и везде, даёт `404`. Не чаще одного
запроса в 2 секунды на человека и плату.

**API** (после входа; POST с `X-Dash-Action: 1` и `application/json`): `GET /api/settings?device=<имя>`
(значения платы, ждущий запрос, история, описание полей для страницы), `POST /api/settings`
`{"device": "...", "set": {"temp_target": 24.5}}`, `POST /api/settings/cancel` `{"device": "..."}`. Ошибки:
`409` — плата ещё не сообщала настройки (старая прошивка) или не разрешила менять их; `400` — значение вне
пределов или нет изменений.

**Попробовать без платы:** `python dashboard/tools/sim_board.py --token mgd_... --device microgarden-sim`
имитирует плату: присылает настройки по умолчанию и применяет запросы по тем же правилам (`--cloud off` —
разрешение выключено, `--refuse` — каждый запрос отклоняется). Токен выдаёт страница «Платы».

## Безопасность

- Токен платы не открывает страницу, а пароль не принимает данные. Администратор — единственный, чей
  пароль лежит в `.env` (не короче 12 символов, без него сервер не стартует); пароли остальных хранятся
  только как scrypt. Токен из `.env` необязателен, но если задан, то не короче 24 символов.
- **Открытая регистрация означает, что завести запись может любой, кто нашёл адрес.** Поэтому у неё есть
  пределы (таблица выше), кнопка «Закрыть регистрацию» и блокировка людей. Администратор видит все платы,
  показания и журналы всех людей; об этом сказано на странице регистрации.
- Токены хранятся в виде SHA-256 и показываются один раз при создании. В журнал сервера пишутся
  имя платы, номер токена и имя человека, но не токен и не пароль.
- Чужая плата не может писать данные под именем другой: токен привязан к плате, а незарегистрированные
  платы отклоняются (`403`).
- Настройки из панели действуют только там, где владелец сам поставил галочку на плате; и сервер, и плата
  проверяют каждое значение по таблице пределов, а запрос, который плата не взяла за 10 минут, отменяется.
  Через панель нельзя изменить сеть, токен и датчик уровня воды, то есть отрезать плату от панели или снять
  защиту насоса. Если украден вход в панель, самое худшее, что можно сделать, это поменять климат, свет и
  полив в пределах, разрешённых таблицей; на плате такая правка видна в консоли.
- Cookie сессии недоступна скриптам страницы (`HttpOnly`), форма входа и регистрации защищены от
  подделки запроса с чужого сайта, а адрес возврата после входа принимается только внутри сайта.
- После 10 неудачных попыток входа или неверных токенов за 10 минут адрес блокируется на 10 минут.
- Страница отдаётся с запретом встроенных скриптов и стилей (CSP), весь текст журнала
  вставляется как текст.
- Данные в журнале платы: IP-адрес в домашней сети в строке подключения к роутеру и
  сообщения об отказах. Пароль точки доступа и пароль администратора плата печатает только в
  USB-порт, в журнал для отправки они не попадают. Страницы с данными закрыты входом.

## Установка на VPS (administrator@dvinsk.lat)

Схема на этом домене: HTTPS на Traefik (хост 93.127.143.133), за ним nginx на VPS, как у
`todo.dvinsk.lat`. Поэтому на VPS certbot не нужен.

1. **Приложение** (права root не нужны). С рабочего компьютера из корня репозитория:

   ```sh
   bash dashboard/deploy/deploy.sh
   ```

   Скрипт копирует файлы в `~/dash` на VPS, при первом запуске создаёт `~/dash/.env` со
   случайными токеном и паролем (права 600), запускает приложение под pm2 как `dash` и
   проверяет `/healthz`. Повторный запуск обновляет код, база `data/` и секреты не меняются.
   При обновлении со старой версии уже работающие платы регистрируются сами (см. «Платы и токены»).
2. **nginx** (нужен sudo с паролем): `sudo bash ~/dash/deploy/enable-nginx.sh` на VPS.
3. **DNS**: запись A `dash.dvinsk.lat` → `93.127.143.133`.
4. **Traefik** на хосте 93.127.143.133: маршрут `Host(dash.dvinsk.lat)` на nginx гостя. Проще
   всего скопировать маршрут `todo`; пример — `deploy/traefik-dash.example.yml`.
5. Пароль администратора: `ssh kicad-vps 'grep VIEW_PASSWORD ~/dash/.env'`, имя `garden`: войти можно
   формой на `/login`. Остальные люди регистрируются сами на `/register`, токены плат создаются в браузере
   на странице «Платы», по ssh они не нужны. Токен, который `deploy.sh` записал в `.env` при установке,
   остаётся рабочим как общий токен администратора.

Проверка: `https://dash.dvinsk.lat/healthz` отвечает `ok`, главная страница ведёт на форму входа.

**Обновление с версии без учётных записей** (только код, база и `.env` остаются): при первом запуске
создаются таблицы людей и сессий, у плат появляется владелец, а все существующие платы достаются
администратору и продолжают работать с прежним токеном. Браузер, в котором вы входили по паролю в окне
браузера, какое-то время может оставаться «вошедшим» (он сам присылает сохранённый пароль), потом вход идёт
через форму. Если нужно закрыть регистрацию до первого запуска, поставьте в `.env` `DASH_REGISTRATION=closed`.

Обслуживание на VPS:

```sh
pm2 logs dash --lines 50          # журнал приложения
pm2 restart dash                  # перезапуск
sqlite3 ~/dash/data/dash.sqlite3 ".backup '/home/administrator/dash-backup.sqlite3'"   # копия базы
```

Сроки хранения задаются в `.env`: `DASH_RETENTION_DAYS` (показания, по умолчанию 400) и
`DASH_LOG_RETENTION_DAYS` (сообщения, 90). Рост базы: около 4,3 МБ в месяц на одну плату при
записи раз в минуту (измерено на демо-данных), то есть порядка 55 МБ за срок хранения 400 суток.

## Что не проверено

- Установка на VPS и переход боевой базы на учётные записи: тесты и просмотр в браузере выполнены на
  локальной копии с выдуманными данными, переход проверен на имитации старой базы.
- Открытая регистрация в интернете: пределы проверены тестами, но не под нагрузкой и не против настоящих
  ботов. Что письма нет (сброс пароля только руками администратора) и что администратор видит чужие данные,
  это решения, а не недосмотр.
- Работа с настоящей платой в основном не менялась: протокол приёма тот же, добавились проверки владельца и
  частота (не чаще раза в 5 секунд), которую обычная плата не нарушает.
- **Настройки из панели проверены без железа.** Прошивка собрана, правила разбора ответа проверены на этапе
  сборки (`static_assert`), сервер и страница проверены тестами и на имитации платы (`tools/sim_board.py`). На
  настоящей плате изменение не применялось: перед выкладкой нужно прошить плату, загрузить её страницы
  (SPIFFS), поставить галочку и проверить на безопасном значении, например яркости индикатора.
- Вид страниц на телефоне проверен в окне шириной 500 px, а не на настоящем телефоне.
