# Прошивка MicroGarden V1 / EU-LITE

Адаптация прошивки контроллера EU-0.1 для автономного проекта MicroGarden V1.
Исходник скетча — `firmware.ino`; файлы веб-интерфейса и настроек лежат в `data/`.
Плата использует ESP32-WROOM-32E-N4 и совместимую с классическим ESP32 плату
Arduino ESP32.

## Изменения для Lite

- INA238 по I²C `0x40`; драйвер проверяет производителя/модель, конфигурацию и
  ошибку памяти регистра перед использованием измерений. Масштаб шунта — 3,5 мΩ.
- Только один LED канал на GPIO25. Минимум PWM — 5 отсчётов при 1 кГц/8 бит
  (19,53 мкс), чтобы соответствовать расчётному минимальному импульсу силового
  каскада (14,69 мкс при уставке 69 Вт и 283,45 кГц). Порог не менялся: он
  по-прежнему выше расчёта.
- Тахометров вентиляторов нет. API сохраняет поля `fan1_rpm` и `fan2_rpm` со
  значением `null` и сообщает `fan_tach_available: false`.
- RGB-индикатор на GPIO4/16/17 показывает неисправности самой платы: датчики,
  RTC, питание и SD. Светится ровно, без мигания; каждый канал либо полностью
  включён, либо выключен — смешанных оттенков и промежуточных яркостей нет.
  Ход работы (помпа, нагреватель, отправка телеметрии) и связь с роутером
  индикатором не показываются, это видно в веб-интерфейсе.

  | Цвет | Значение |
  |---|---|
  | Синий | идёт инициализация в `setup()` |
  | Красный | SHT4x не отвечает или времени RTC нет доверия |
  | Пурпурный | просадка шины: подача на LED заблокирована |
  | Жёлтый | нет SD-карты или нет данных INA238 |
  | Зелёный | норма |

  Проверки идут сверху вниз: более тяжёлая неисправность перекрывает более лёгкую.
  Синий гаснет, как только `loop()` впервые обновляет индикатор, поэтому
  задержавшийся синий означает, что плата не дошла до рабочего цикла.
  Та же расшифровка цветов есть на странице настроек (вкладка «Общее», под настройками индикатора);
  тест `tests/settings.test.cjs` следит, чтобы список цветов на странице совпадал с `StatusColor`
  в `LiteControl.h`.

  **Настройки** (страница настроек, вкладка «Общее», раздел «RGB-индикатор»), применяются сразу:
  - *Яркость, %* — от 0 до 100; 0 выключает индикатор совсем (неисправности тогда видны только на
    странице). По умолчанию 19 %, это прежняя постоянная яркость (48 из 255).
  - *Ночью* — «как днём» (по умолчанию), «только неисправности» (зелёный гаснет, красный,
    пурпурный и жёлтый остаются) или «выключен». Ночь — время вне расписания света на вкладке
    «Освещение»: индикатор светит в тёмный период растений, поэтому его можно приглушить.
    Синий при запуске (`setup()`) настройки не учитывает.
- LED блокируется, если измеренное напряжение шины ниже 21,6 В. Повторное разрешение
  происходит при достоверном напряжении от 22,5 В. Одиночный пропущенный отсчёт INA238
  решение не меняет, а холодный пуск ждёт первого измерения. Если измеритель не отвечает
  совсем (не впаян, отказал, три чтения подряд неудачны), свет **не гасится**, пока плата
  знает время (RTC) и датчик SHT4x показывает климат; без времени или без датчика свет
  выключается. Решение владельца от 27.10.2026: отказ измерителя не должен оставлять
  растения без света. Плата пишет в журнал «[Power] Нет связи с измерителем питания»,
  страница показывает предупреждение, RGB остаётся жёлтым.
  В Lite нет аппаратной UVLO/PGOOD-блокировки: **пока измеритель молчит, защиты от
  просадки питания нет**, она зависит от ESP32 и исправного INA238.

## Время: RTC и программный таймер

Расписание полива и свет без измерителя питания (см. выше) работают, пока у платы есть время:
либо RTC отвечает и время в нём достоверно, либо **программный таймер** выставлен настоящим
источником с момента запуска: чтением RTC (потом RTC отказал) или временем, которое владелец ввёл
на странице настроек. Таймер идёт по `millis()` и уходит порядка секунд в сутки; до перезагрузки
этого хватает для полива. Дефолтная дата, с которой плата стартует при мёртвом RTC, источником не
считается: пока время не выставлено, полив и свет без измерителя выключены.

- RTC не отвечает, но время есть: RGB красный, в колокольчике на главной странице жёлтое оповещение
  «Часы RTC не отвечают: время идёт по программному таймеру до перезагрузки, полив работает», в журнале
  при старте полива появляется пометка «(время по программному таймеру, RTC не отвечает)». Если времени
  нет совсем, оповещение красное: «полив выключен, пока время не выставлено». Отдельной полосы про часы
  в шапке главной страницы больше нет, всё собрано в колокольчике.
- После перезагрузки при мёртвом RTC таймер теряется: время нужно ввести снова (вкладка
  «Общее»), иначе полив не начнётся. Замените или проверьте RTC: [стендовый список](../hardware/PCB_EU_LITE/review/Bench_checklist.md).
- Дата в карточках («День цикла», день/ночь) считается по тому же времени. При невыставленном
  времени она не соответствует действительности.

## Оповещения на главной странице

Колокольчик в шапке главной страницы показывает число активных оповещений, по нажатию открывает
их список. Это **текущие неисправности**, а не журнал: оповещение пропадает, когда причина
устранена; история событий остаётся на вкладке «Консоль». Цвет колокольчика и счётчика — по
самому тяжёлому оповещению: серый (нет оповещений), жёлтый (предупреждения), красный
(что-то не работает); при росте числа оповещений колокольчик качается. В заголовке вкладки
браузера тоже стоит число, например «(2) MicroGarden V1».

| Оповещение | Уровень | Условие в `/api/status` |
|---|---|---|
| Датчик SHT4x не отвечает | красный | `sht_online = false` |
| Часы RTC не отвечают или не выставлены | красный без времени, жёлтый на программном таймере | `clock_trusted = false`, `clock_usable` |
| Свет выключен: питание ниже 21,6 В | красный | `power_ok` и `led_supply_blocked` |
| Свет выключен: нет данных питания и нет времени или датчика | красный | `power_ok = false` и `led_supply_blocked` |
| Измеритель питания не отвечает, свет работает без защиты | жёлтый | `power_ok = false`, свет не заблокирован |
| В баке нет воды | жёлтый | `water_sensor_enabled` и `water_present = false` |
| Последний полив пропущен | жёлтый | `last_water_skipped` |
| SD-карта не обнаружена | жёлтый | `sd_ok = false` |
| Нет связи с платой (показания страницы устарели) | красный | страница не получила ответ 10 с |

В режиме сушки оповещения про свет и полив не показываются. Правила лежат в
`firmware/data/alerts.js` и проверяются `tests/alerts.test.cjs`.

## Отправка телеметрии

Раз в минуту плата отправляет показания и новые строки журнала (то же, что идёт в Serial и во
вкладку «Консоль») на сервер панели из [dashboard/](../dashboard/README.md), по умолчанию
`https://dash.dvinsk.lat/api/ingest`. Формат запроса — в [dashboard/README.md](../dashboard/README.md#что-присылает-плата).

- **Включение.** Пока токен приёма не задан, плата ничего не отправляет. Адрес, имя платы и токен
  вводятся на странице настроек, вкладка «WiFi», раздел «Телеметрия»; токен выдаёт сервер
  (`~/dash/.env`, `DASH_INGEST_TOKEN`) и обратно через интерфейс не возвращается. Нужен WiFi
  роутера и выход в интернет.
- **Безопасность.** Только `https`. Сертификат сервера проверяется по закреплённому корню ISRG Root X1
  ([DashCA.h](DashCA.h), действует до 2035 года); для проверки срока сертификата плата получает время UTC
  по NTP (`pool.ntp.org`, `time.cloudflare.com`), RTC платы это не меняет. Пароли точки доступа и
  администратора печатаются только в USB и в журнал для отправки не попадают.
- **Журнал.** Плата отправляет только целые строки, а смещение в байтах и случайный номер запуска
  позволяют серверу принять повтор безопасно и пометить пропуск или перезагрузку. Если кольцевой
  буфер (4 КБ) переполнился между отправками, пропущенная часть помечается на странице.
- **Влияние на работу.** Задача работает на Core 0 только на чтение снимков состояния и настроек.
  Недоступность сети, сервера или сертификата на свет, вентиляторы, нагрев и полив не влияет.
  Итог отправки пишется в журнал при смене результата и раз в полчаса при затянувшейся ошибке.
- **Память.** HTTPS (mbedTLS) возвращает в прошивку задачу со стеком 12 КБ и около 130 КБ флеша:
  образ вырос с 84 % до 94 % раздела приложения (1 237 230 из 1 310 720 байт, свободно около 73 КБ),
  оперативная память — с 17 % до 19 %. Для новых функций запас небольшой.

Остальные функции унаследованы от EU-0.1. Сохраняются имена настроек и NVS,
поэтому существующие параметры не нужно мигрировать.

## Сборка

Установите Arduino CLI и ESP32 Arduino Core 3.x, затем из корня репозитория:

```sh
arduino-cli compile --fqbn esp32:esp32:esp32 firmware
```

Нужные сторонние библиотеки: `RTClib`, `Adafruit SHT4x`, `ESPAsyncWebServer`
и её зависимость `AsyncTCP`. Установите их через Library Manager или Arduino
CLI. Остальные компоненты в `#include` предоставляет ESP32 Arduino Core.
INA238 реализована локально в `Ina238.h` и внешней библиотекой не требует.

После прошивки скетча отдельно соберите и загрузите файловую систему SPIFFS из
каталога `firmware/data` для того же ESP32. В ней хранятся веб-страницы и
JavaScript; одна сборка скетча их не загружает. Перед выпуском проверьте объём
раздела файловой системы и выберите ту же схему разделов при загрузке.

В исходниках есть compile-time проверки минимального LED импульса и INA238;
запустите также host-регрессии:

```sh
node --test tests/settings.test.cjs
python tools/check_standalone.py
```

## Первое включение

Сборка исходника не является квалификацией устройства. До подключения LED,
нагревателя и помпы пройдите [стендовый список](../hardware/PCB_EU_LITE/review/Bench_checklist.md):
проверьте выходы без нагрузки, аварийное отключение, показания INA238,
просадку питания, RTC, SD и работу датчиков. Для проверки порога отключения
света используйте ограниченный лабораторный источник и безопасную тестовую
нагрузку. Физическую защиту и температурные пределы подтвердите измерениями.
